- 背景

  コンテナで動かすサービスを追加するとき、「どのポートが使えるか」を確認が必要となるため、「開いているポートの確認方法」をまとめる。

  Ubuntu 26.04 LTSでは、`sudo`がRust製の`sudo-rs`に、`coreutils`もRust製のものに置き換わっている。ただし、ここで扱う`ss`・`lsof`は、置き換えの対象とは別のパッケージであり、基本的な使い方は24.04と同じである。`sudo`を付けた実行も、従来と同じ書き方でよい（パスワード入力中に`*`が表示される点だけが、従来と異なる）。


- 接続待ちのポートを確認する

  サーバー上でどのサービスが動いていて、どのポートで外部からの接続を待ち受けているか（LISTEN状態か）を確認することは、セキュリティ管理やトラブルシューティングの基本である。最近のLinuxでは、従来の`netstat`に代わり、`ss`コマンドの使用が推奨されている。

  - **接続待ちのポートを一覧する:**

     ```bash
     ss -tuln
     ```

     現在、**接続待ちの状態にあるTCP/UDPのポート**を、ポート番号の数値で表示する。一覧を見るだけなら、`sudo`は不要である。

     | オプション | 意味 |
     | --- | --- |
     | `-t` | TCPソケットを表示 |
     | `-u` | UDPソケットを表示 |
     | `-l` | **LISTEN（接続待ち）**状態のソケットのみ表示 |
     | `-n` | ポート番号を数値で表示（名前解決をしないため高速） |

     UDPは接続という概念がないため、状態の欄には`LISTEN`ではなく`UNCONN`と表示される。

  - **使用しているプロセスも表示する:**

     ```bash
     sudo ss -tulnp
     ```

     `-p`を付けると、ポートを使っているプロセス名とPIDも表示される。他のユーザー（rootなど）のプロセスの情報を見るには、`sudo`が必要である。

  - **特定のポートの状態を確認する:**

     たとえば、Webサーバーの**80番ポート**が接続待ちになっているかを確認する場合は、次のように書く。

     ```bash
     # ssコマンドで確認（ポート番号で絞り込む）
     ss -tuln 'sport = :80'

     # lsofコマンドで確認
     sudo lsof -i :80
     ```

     > ⚠️ `ss -tuln | grep :80`と書くと、`:8080`や`:8000`のように`:80`で始まる別のポートにも一致してしまう。「80番が使われている」と誤認しやすいため、コンテナの公開ポートを選ぶときは、`'sport = :80'`の形で絞り込む。

- **プロセスとポートの対応を確認する:**

  **どのアプリケーションがそのポートを使っているか**まで確認したい場合は、`lsof`（list open files）コマンドが強力である。

     ```bash
     # TCPの接続待ちを表示
     sudo lsof -iTCP -sTCP:LISTEN -P -n

     # UDPを表示
     sudo lsof -iUDP -P -n
     ```

     | オプション | 意味 |
     | --- | --- |
     | `-iTCP` / `-iUDP` | ネットワーク接続のうち、TCP / UDPのみを対象にする |
     | `-sTCP:LISTEN` | TCPの接続待ち（LISTEN）状態のみ表示する |
     | `-P` | ポート番号を数値で表示する（サービス名に変換しない） |
     | `-n` | ホスト名の名前解決をしない |

     `lsof -i -P -n | grep LISTEN`と書く方法もあるが、これはTCPの接続待ちだけが対象で、UDPは表示されない。UDPは前述のとおり`LISTEN`の状態を持たないためである。`lsof`が入っていない環境では、`sudo apt install lsof`でインストールする。

     出力される項目の意味は次のとおり。

     | 出力項目 | 意味 |
     | --- | --- |
     | `COMMAND` | サービスを起動しているプロセス名 |
     | `PID` | プロセスID |
     | `NAME` | **ローカルアドレス:ポート番号**（例: `*:22`） |

- **見えるのは「サーバー内で待ち受けているポート」だけ:**

  - `ss`や`lsof`が示すのは、サーバー内で接続待ちをしているポートである。外部から実際に届くかどうかは、UFWなどのファイアウォールの設定による。UFWの有効化は、[Ubuntu 26.04 LTSの導入(その7) ファイアウォール(UFW)の有効化](https://kazukif-blog.pages.dev/posts/infra/install_ubuntu2604-7/)で扱っている
  - Dockerのコンテナが公開したポートも、ホスト側で接続待ちとして表示されることが多い。なお、Docker EngineとUFWのルールは相互連携しないため、コンテナで公開したポートは、UFWで閉じていても外部から届く場合がある
